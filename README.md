# mips_ori：单周期 MIPS CPU —— `ori` 指令原理与实现

## 1. 指令功能

`ori`（OR Immediate，逻辑或立即数）是 MIPS 的 I 型指令：

```
ori rt, rs, imm      # rt <- rs | {16'h0000, imm}
```

把 16 位立即数**零扩展**成 32 位，与 `rs` 的值按位或，结果写入 `rt`。

## 2. 指令编码

| 31..26 | 25..21 | 20..16 | 15..0 |
|--------|--------|--------|-------|
| opcode = 001101 (0x0D) | rs | rt | imm16 |

编码示例：`ori $1, $0, 0x1100`

```
001101  00000  00001  0001000100000000
  op      rs     rt         imm16
= 0011 0100 0000 0001 0001 0001 0000 0000
= 0x3401_1100
```

注意字段跨越十六进制位边界，最稳的办法是先把 op/rs/rt/imm 的二进制串拼接，
再从左往右每 4 位一组换算成 hex。例如 `ori $3, $2, 0x1234`：
`001101 00010 00011 0001001000110100` → **0x3443_1234**。

## 3. 三个关键语义点

1. **零扩展，不是符号扩展**。`ori` 是逻辑指令，立即数按无符号处理，高 16 位补 0：
   - `ori $4, $0, 0xFFFF` → `$4 = 0x0000_FFFF`（而不是 0xFFFF_FFFF）
   - 对比：`addi` 是算术指令，立即数做**符号**扩展。
   - 因此 `ori` 常用于给寄存器装载 16 位常数；装载 32 位常数时用 `lui` + `ori` 组合。
2. **`$0` 恒为 0**。任何对 `$0` 的写入都必须被忽略。
3. **单周期实现中每条指令恰好 1 个时钟周期完成**。

## 4. 单周期数据通路

```
        ┌─────┐    ┌───────────┐    ┌─────────────────┐    ┌───────────┐
        │ PC  │───►│ inst_rom  │───►│    id (译码)     │───►│ ex (ALU)  │
        └─────┘    └───────────┘    └────────┬────────┘    └─────┬─────┘
          ▲          按 pc 取指              │ 读 rs            │
          │ pc+4                            ▼                  │ rs | imm
        ┌──────────────────────────────────────────────────────┐│
        │        regfile（时钟上升沿写回，$0 恒 0）              │◄┘
        └──────────────────────────────────────────────────────┘
```

一个时钟周期内，组合逻辑依次流过：**取指 → 译码 → 读寄存器 → ALU → 生成写回数据**；
周期结束的时钟上升沿统一做两件事：

1. `PC <= PC + 4`（取下一条指令）；
2. 把本拍算出的 `wb_wdata` 写入 `wb_wdest` 寄存器（若 `wb_we` 有效）。

本设计中 `ori` 的数据流：

| 步骤 | 模块 | 动作 |
|------|------|------|
| 取指 | `inst_rom` | 用 `pc` 当地址读出 32 位指令 |
| 译码 | `id` | 判断 `opcode == 001101`；拆出 rs/rt/imm；`imm` 零扩展为 `{16'h0, imm}`；输出读地址去寄存器堆读 `rs` |
| 执行 | `ex` | ALU 计算 `rs_value | zext_imm` |
| 写回 | `regfile` | 时钟沿写入 `rt`；`rt == $0` 时无写使能 |

## 5. 模块划分 (rtl/)

| 文件 | 职责 |
|------|------|
| [pc_reg.v](rtl/pc_reg.v) | 程序计数器：复位清零，每拍 +4 |
| [inst_rom.v](rtl/inst_rom.v) | 指令 ROM：`$readmemh` 加载 hex，按 pc 按字取指；剩余空间填 0（译码后不命中 ori，等效 nop） |
| [regfile.v](rtl/regfile.v) | 32×32 寄存器堆：同步写 / 异步读；**$0 双重保护**（读恒 0 + 写被忽略） |
| [id.v](rtl/id.v) | 译码：识别 ori、拆字段、零扩展 imm、读 rs；`rt=$0` 时不产生写使能 |
| [ex.v](rtl/ex.v) | ALU：按 `alu_op` 计算（当前只有 OR，结构上留了扩展位） |
| [mips_core.v](rtl/mips_core.v) | 顶层：把上述模块连成单周期通路 |

设计要点：

- **写 $0 的保护做了两层**：`id` 层面对 `rt == 0` 不给写使能；`regfile` 内部再拦一次。testbench 把"CPU 试图写 $0"当作错误上报。
- **复位期间 `id` 输出全零写使能**，保证第一条指令不会被复位打断而误写。
- **未知指令不写任何寄存器**（等效 nop），为后续扩展其他指令留好了骨架。

## 6. 测试程序 (sim/inst_rom.data)

| # | 汇编 | 机器码 | 预期结果 | 验证点 |
|---|------|--------|----------|--------|
| 1 | `ori $1, $0, 0x1100` | 0x34011100 | $1 = 0x00001100 | 基本取指→译码→写回通路 |
| 2 | `ori $1, $1, 0x00FF` | 0x342100FF | $1 = 0x000011FF | 读写同一寄存器（用旧值） |
| 3 | `ori $2, $0, 0xABCD` | 0x3402ABCD | $2 = 0x0000ABCD | 装载立即数 |
| 4 | `ori $3, $2, 0x1234` | 0x34431234 | $3 = 0x0000BBFD | rs 与 imm 按位或 |
| 5 | `ori $0, $0, 0xFFFF` | 0x3400FFFF | $0 仍为 0 | 写 $0 被忽略 |
| 6 | `ori $4, $0, 0xFFFF` | 0x3404FFFF | $4 = 0x0000FFFF | **零扩展**（≠ 0xFFFFFFFF） |

0xABCD | 0x1234 = 1010_1011_1100_1101 | 0001_0010_0011_0100 = 1011_1011_1111_1101 = 0xBBFD。

## 7. 测试平台 (sim/tb_mips_ori.v)

- 不直接窥探内部寄存器，而是监视顶层写回端口 `wb_we / wb_wdest / wb_wdata`，
  在 testbench 里维护一个"**影子寄存器堆**"——验证的是 CPU 对外的写回行为，更接近真实接口；
- CPU 若试图写 `$0`，直接记 ERROR；
- 全部执行完后逐项比对 5 个预期值，输出 `==== ALL TESTS PASSED ====`。

## 8. 如何仿真

需要 iverilog（Windows 可在 WSL 中 `sudo apt install iverilog`）：

```bash
cd sim
iverilog -g2005 -o sim.vvp ../rtl/*.v tb_mips_ori.v
vvp sim.vvp
```

预期输出：5 次写回（第 5 条 `ori $0` 无写回）+ 5 行 PASS + `==== ALL TESTS PASSED ====`。

开头的 `$readmemh ... Not enough words` 警告是正常的：指令文件只有 6 条，
ROM 共 64 字，其余空间已在 initial 中预填 0。

## 9. 后续扩展其他指令

只需三步：

1. [id.v](rtl/id.v)：加 opcode/funct 判断，产生新的 `alu_op`；需要时改变操作数来源
   （例如 `addi` 把立即数改成符号扩展 `{16{imm[15]}, imm}`）；
2. [ex.v](rtl/ex.v)：给 ALU `case` 加运算分支；
3. 在 `sim/inst_rom.data` 加测试指令，并在 testbench 的 `expected` 里补期望值。
